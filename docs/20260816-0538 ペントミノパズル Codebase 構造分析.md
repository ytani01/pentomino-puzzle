# ペントミノパズル Codebase 構造分析ドキュメント

## 1. 結論（アーキテクチャの概要）

本リポジトリは、**ビルド工程なしの純粋な ES Modules と Phaser 3（CDN参照）** で構成された2Dパズルゲームです。  
アーキテクチャは**「Phaser/DOM依存なしの純粋ロジック層」「事前計算データ層」「UI・シーン制御層」**の3層に明確に分離されており、テスト容易性とパフォーマンス（応答速度 1ms 台のヒント・詰み判定）を両立しています。

---

## 2. 各モジュールの役割分担

### 2.1 コアロジック・データ層 (DOM / Phaser 非依存)

| モジュール名 | 役割・責務 | 技術的事実に基づく根拠 |
| :--- | :--- | :--- |
| `src/config.js` | 定数・レイアウト計算・定義情報管理 | 画面サイズ(`SCREEN`)、盤面定義(`BOARDS`)、ピース定義(`PIECES`)、カラーパレット(`PALETTES`)、動的レイアウト計算関数(`makeLayout`)などを保持。 |
| `src/logic.js` | 純粋なパズル計算ロジック | ピースの正規化(`normalize`)・回転/反転(`rotateCw`, `flip`, `turnOrder`)・盤面座標計算・配置可否判定(`canPlace`)・境界輪郭抽出(`outlineEdges`)・代表形変換(`canonicalBoard`)等の純粋関数群。テストコード(`tests.html`)から直接検証される。 |
| `src/solutions.js` | 全解データ管理・検索 | 事前生成された解データファイル(`src/data/*.js`)の動的importと、代表形から見た目の全解への展開(`buildSolutions`。展開に使う変換は `logic.js` の `boardSymmetries`)、および条件に合う解の検索(`hasSolution`, `autoFrom`)を担当。 |
| `src/data/8x8.js`<br>`src/data/6x10.js` | 事前計算された全解データ | 代表形の文字列配列（8×8: 65件、6×10: 2,339件）を保持。 |
| `src/storage.js` | 永続化ストレージ操作 (`localStorage`) | 自己ベスト時間・クリア履歴・達成度（発見した解の番号）・おまかせで導いた解の番号・遊びかけの盤面（TODO-030）・カラーパレット設定の読み書きと、不正な保存データの不整合防止フィルタ(`sanitizeHistory`, `sanitizeProgress`)を担当。 |

### 2.2 表現・演出層

| モジュール名 | 役割・責務 | 技術的事実に基づく根拠 |
| :--- | :--- | :--- |
| `src/ui.js` | 共通UIコンポーネント | PhaserのGraphics APIを用いたボタン(`createButton`)、パネル(`createPanel`)描画およびレイアウトの垂直整列補正(`stackTops`)を提供。 |
| `src/audio.js` | Web Audio API 効果音合成 | アセット画像/音声ファイルを持たない方針に基づき、Web Audio APIを用いてクリック音・配置音・ファンファーレなどの効果音を動的合成・発声。 |

### 2.3 シーン制御層 (Phaser.Scene)

| モジュール名 | 役割・責務 | 技術的事実に基づく根拠 |
| :--- | :--- | :--- |
| `src/main.js` | エントリーポイント | Phaser.Gameインスタンス生成、解像度・スケール設定 (`Phaser.Scale.FIT`)、シーン配列の登録。 |
| `src/scenes/boot.js` | 初期化・テクスチャ動的生成 | `Boot` シーン。各盤面・パレットサイズに応じたマス目・ピースのテクスチャを Graphics API で動的生成し、`this.textures` に登録後、`Title` シーンへ遷移。 |
| `src/scenes/title.js` | タイトル画面・設定変更 | `Title` シーン。盤面サイズ選択 (8×8 / 6×10)、カラーパレット選択 (glass / colorful)、操作説明表示、記録画面および本編シーンへの遷移制御。遊びかけがあれば `つづきから` で再開させる (TODO-030)。 |
| `src/scenes/game.js` | ゲーム本編インタラクション | `Game` シーン。ピースのドラッグ＆ドロップ、タップによる向きの巡回 (TODO-019・TODO-025。ダブルタップ反転は TODO-023 で廃止)、Undo、ゴースト表示、詰み判定、おまかせ、ヒント表示、タイマー計測、タイトル戻り確認パネルの制御。 |
| `src/scenes/clear.js` | クリア画面・記録保存 | `Clear` シーン。クリアタイム・正解番号の表示と記録の更新。最短時間 (`saveBest`) はおまかせ・ヒント表示のどちらも使わなかった回だけ更新し (`shouldRecordBest`)、履歴と達成度 (`addHistory`, `addFound`) は頼った回も印を付けて残す (TODO-024)。 |
| `src/scenes/records.js` | クリア記録・達成度閲覧 | `Records` シーン。過去のクリア履歴の一覧表示（ページ送り）、選択した履歴の完成形ミニマップ描画、全解に対する発見達成度の表示、選んだ 1 件の削除 (TODO-031)。 |

### 2.4 生成・検証ツール (`tools/`)

| モジュール名 | 役割・責務 | 技術的事実に基づく根拠 |
| :--- | :--- | :--- |
| `tools/enumerate.mjs` | 求解探索エンジン | 深さ優先探索＋2つの枝刈り（空きマス若い順＋空き領域の5の倍数チェック）により全解を完全列挙。 |
| `tools/gen-solutions.mjs` | 解データ生成・差分検証スクリプト | `enumerate.mjs` を実行して `src/data/*.js` を生成。CI (`.github/workflows/pages.yml`) では `--check` フラグでデータ不整合を検出。 |
| `tools/window-shim.mjs` | Node.js環境用ダミーモジュール | `src/config.js` 等が参照する `window` オブジェクトを Node.js 環境上でモック化。 |

## 3. モジュール間の呼び出し関係・データフロー

### 3.1 シーン遷移フロー

```
  [ Boot ]
     │ (テクスチャ動的生成)
     ▼
  [ Title ] ─────────────────────► [ Records ]
     │ (盤面・カラーパレット選択、        ▲ (記録一覧・完成形・達成度)
     │  「はじめる」/「つづきから」)      │
     ▼                                   │
  [ Game ]                               │
     │ (パズルクリア)                     │
     ▼                                   │
  [ Clear ] ─────────────────────────────┘ (「記録」ボタン。TODO-032)
     │ (「もう一度」/「タイトルへ」)
     └───────► [ Game ] / [ Title ]

  Records の「タイトルへ」で [ Title ] に戻る。Game からタイトルへ戻るときは
  確認パネルを挟み、盤面は遊びかけとして保存される（TODO-030）。
```

### 3.2 データフローと状態管理

1. **シーン間データ共有 (`this.registry`)**:
   - `BOARD_REGISTRY_KEY` (選択中の盤面種別 `'8x8'` または `'6x10'`)
   - `PALETTE_REGISTRY_KEY` (選択中のパレット `'glass'` または `'colorful'`)
   - `solutions/<盤>` (読み込み済みの解データオブジェクト。キーは `solutions.js` の `solutionsRegistryKey()` が `SOLUTIONS_REGISTRY_PREFIX` から作る)
2. **本編中の操作フロー (`src/scenes/game.js`)**:
   - ユーザー入力 (ドラッグ / タップ) ➔ `logic.js` (`canPlace`, `nextTurn`, `nextPlaceableTurn`) で検証 ➔ 盤面状態更新
   - 状態更新時 ➔ `solutions.js` (`hasSolution`) を参照してリアルタイム詰み判定。`おまかせ` は `autoFrom` で 1 手ぶんを取る
3. **クリア・保存フロー (`src/scenes/clear.js`)**:
   - ゲームクリア検知 ➔ `storage.js` (`shouldRecordBest`) で判定 ➔ 自力クリア時のみ `saveBest` で最短時間を更新。履歴と達成度 (`addHistory` / `addFound`) は、おまかせ・ヒント表示に頼った回も印付きで `localStorage` へ永続化する (TODO-024)。

## 4. 技術的特徴と設計根拠

1. **グラフィック・音声アセットの完全撤廃**:
   - 画像ファイルや音声アセットをリポジトリ内に保持せず、`boot.js` による Canvas Graphics テクスチャ生成と `audio.js` による Web Audio API 定義音源のみでゲーム画面・効果音を構築。
2. **計算処理の完全事前実行 (全解データの静的保持)**:
   - 実行時のバックトラック探索による画面スリープ（6×10盤面等での数秒間のフリーズ）を回避するため、全解（8×8: 65代表形 / 520解、6×10: 2339代表形 / 9356解）を `tools/gen-solutions.mjs` で事前計算し、`src/data/*.js` として固定データ化。
3. **ロジックの完全分離と単体テスト駆動**:
   - `logic.js` にPhaserやDOM依存のコードを一切含めず純粋関数化することで、`tests.html` において100件以上の単体テストを高速に実行可能。

## 5. コード例・命名規則に関する注意事項

本プロジェクトのコード・設定例などでサンプル識別子を使用する場合は、慣例に従い `foo` や `bar` などの識別子を使用し、禁止文字列（例: `hoge`）は使用しない設計としています。
