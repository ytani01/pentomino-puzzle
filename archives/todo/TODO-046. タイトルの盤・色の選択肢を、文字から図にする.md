## きっかけ

利用者の依頼（2026-09-24）。「タイトルで、文字をアイコンなどにしたい。板の選択肢は
板の形を図形で、色は 2×1 ぐらいのピースを色付きで。細かいことは任せる」。
範囲は盤と色の 2 行だけにし、`はじめる`・`つづきから`・`記録`・`デモ` と、
行頭の見出し「盤」「色」は文字のまま残した（利用者が選んだ）。
着手の前に、実際のタイトル画面へブラウザ上で図を描き足したサンプルを見せて、見た目の了承を得た。

## やったこと

- `src/icons.js` に `boardIcon(board)` と `paletteIcon(palette)` を足した。
  どちらも `createButton()` の `icon` に渡す `(graphics, color) => void` を返す
  - 盤: `boardCells()`（`logic.js`）の置けるマスを小さな正方形で塗る。
    色はボタンの状態の色を使うので、選んだ盤は強調色になる
  - 色: 2×1 の小片を 3 つ（F・P・V の色）。塗り・マスの区切り・外周の色と太さを
    盤のマス目（`boot.js`）とピースの外周（`game.js`）に揃え、外周は線の太さの
    半分だけ内側へ寄せる。12 色の立体感、ガラスの光の筋、ネオンのにじみは描かない
- マス目テクスチャを縮めて貼る案は、サンプルで蛍光の組の縁が細くなって暗く沈んだのでやめた
- `src/config.js` に寸法の `CHOICE_ICON` を足した
- `src/ui.js` の `createChoiceRow` が、選択肢の `icon` と `tooltip` を `createButton` へ渡すようにした。
  記録の画面は今までどおり文字で出る（渡さなければ既定値の `null`）
- `src/scenes/title.js` で、盤・色の選択肢に図と説明（「8×8（中央 2×2 は穴）」「ガラス」など）を付け、
  `createTooltip()` で説明の枠を作った
- `CLAUDE.md` のファイル構成の表で、`src/icons.js` の役割を書き足した

## 分担の振り返り

- **reviewer** は、色の見本の区切り線と外周が本編の規則と違うこと、穴の判定の書き直し、
  効いていない rows / cols の入れ替え、古くなったコメント 4 か所を見つけた。main の見落としだった
- **screens** は何も見つけられなかった。2 回とも、画面を 2 枚撮ったあとの最初のクリックで、
  Playwright の `mouse.click` が返らなくなった（クリックはページに届いていた）。
  main も同じタブで同じところで止まり、タブを閉じて開き直すと直った。
  固まったきっかけは切り分けられなかった（CDP でのキャッシュ消去・画面サイズの変更・
  初めて音を鳴らすクリックは、どれも新しいタブでは再現しなかった）。
  1 回目の依頼は「5 つのボタンを全部押す」「5 つ全部にマウスを載せる」と操作が多く、
  利用者から回数が多すぎると指摘された
- **verifier** は食い違いを見つけなかった。main が撮った画像の判定だけなので、安く済んだ
- 見込みとの食い違いは、ブラウザが固まったことによる。screens の分の料金は小さいが、
  止まっていた約 1 時間ぶん利用者を待たせた
- 次に同じ規模の画面の項目をやるなら:
  - 撮影の担当には、始める前にタブを開き直させ、クリックなどの操作に時間の上限
    （`Promise.race` と `page.waitForTimeout`）を付けさせる。固まったらやり直させずに報告させる
  - 同じコードを通る操作は代表 1 つにし、文言は evaluate やコードで一度に確かめる
    （ユーザー全体の `CLAUDE.md` に書き足した）
  - main が撮って verifier が判定する形でも、確認を分ける目的は果たせた。
    screens が固まり続けるなら、こちらを既定にしてよい
