# TODO-023. ピースを動かす操作を速くする

## きっかけ

「向きを変えて、置いてみて、ダメならやり直す」の反復が遅かった。

- タップは `INPUT.doubleTapMs`（320ms）待ってから向きを変えていた。
  ダブルタップの反転（TODO-010）を待つための猶予で、向きを変えるたびに
  この待ちが入る
- 盤に置いたピースをタップして、そこに置けない向きになると赤く光って
  止まる。置ける向きに当たるまでタップし続けることになる
- 置く位置が少しずれるとゴーストが消え、離すと元へ戻される
- 盤から外すには、盤の外まで正確に運んで離す必要があった

## やったこと

案を A〜F として、B 以外を入れた。B（向きの巡る順）は待ちが消えると印象が
変わるので、触ってから決めることにして **TODO-025** へ分けた。

### 案 A — ダブルタップの反転を廃止（`game.js`・`config.js`）

`onPointerUp()` は待たずに `turnPiece()` を呼ぶ。`pendingTap` とその後始末
（`cancelPendingTap()`、`shutdown` での登録）、`INPUT.doubleTapMs` を消した。

8 通りを巡るのに最大 7 タップかかるが（8 通りあるのは F・L・N・P・Y の
5 種で、他は 4 通り以下）、1 回ごとに 320ms 待つより速い。反転を別の
入り口へ移すことはしていない。

### 案 C — タッチのずらし方を画面の向きで変える（`game.js`）

指で隠れないよう、タッチのときだけピースを 1 マスずらす。縦画面では指の上
（今までどおり）、横画面では指の左。マウスはずらさない。

横で左へずらすと指はピースの右に来るが、盤の右端の列へ置くときの指の x は
8×8 で 536、6×10 で 564。トレイの枠（558 / 586）にも画面の右端（960）にも
届かないので、指を画面の外へ出さずに済む。

**`offsetX` が `const` のままで、横画面のタッチだけ例外で落ちていた**
（`Assignment to constant variable`）。リンタが無いので、CDP で実際に
触るまで出なかった。

### 案 D — 振って離せばトレイへ戻す（`game.js`・`config.js`）

`updateDrag()` が直近 `INPUT.swipeWindowMs`（100ms）ぶんの通り道を
`this.drag.trail` に残し、`swipedToTray()` が離す直前の速さを測る。
`INPUT.swipeSpeed`（0.5 px/ms）を超え、向きがトレイの側（縦は下、横は右）で
あれば「置く気は無い」と見て戻す。

位置を合わせて置くときは指が止まってから離れるので、速さで分けられる。
Phaser の `pointer.velocity` は使わず自前で測る。閾値の意味（px/ms）が
はっきりし、`logic.js` の外に Phaser の都合を持ち込まずに済むため。

### 案 E — 置ける升目へ吸い付かせる（`logic.js`・`game.js`）

`snapSpot(board, cells, row, col, range)` を足した。一番近い升目に置けなければ
周りを `INPUT.snapRange`（1 升）まで、近い順に探す。

`dropSpot()` を `nearestSpot()`（一番近い升目）・`nearBoard()`（盤の近くか）・
`snapSpot()` の 3 つに割った。盤の外側 1 升までしか探さないのは、トレイへ
運ぶ途中のピースが盤の縁へ吸い寄せられないようにするため。

D を速さで分けたので、**位置で「戻す」を判断しなくてよくなった**。
そのぶん吸い付く範囲を盤の外まで広げられる。

### 案 F — 置けない向きを飛ばす（`logic.js`・`game.js`）

`nextPlaceableTurn(board, cells, row, col)` を足した。`turnOrder()` を順に見て、
その場に置ける向きまで飛ばす。置けるものが他に無ければ今の向きを返す。

`turnPiece()` が、盤の上のピースには `nextTurn()` の代わりにこれを使う。
どの向きも置けないときだけ、今までどおり赤く光らせて知らせる。

`applyOrientation()` は消して `turnPiece()` にまとめた。ダブルタップが
無くなり、呼ぶのが `turnPiece()` だけになったため。

### 説明の書き換え（`title.js`・`README.md`）

```
ドラッグ … 置く / 動かす
タップ … 次の向きへ（回転と裏返しを順に巡る）
盤から外す … 盤の外で離す / トレイの方へ振る
```

## テスト

`tests.html` に 6 件足して 162 件。`nextPlaceableTurn()` は「返す向きは
その場に置けるか元のまま」を 8×8 の全升目 × 全ピースで確かめ、飛ばす場面と
どの向きも置けない場面を別に見る。`snapSpot()` は寄せ先と、範囲外で
null になることを見る。

見た目と操作は headless Chromium を CDP で動かして確かめた（横 960×640、
縦 640×1136）。

- タップで待ちなしに向きが変わる
- タッチのずれは横で 64px（左）、縦で 67px（上）。マウスは 0
- 振って離すと盤の上でもトレイへ戻る。止めてから離せば置ける
- 一番近い升目が穴と重なる場面で、隣の置ける升目へ吸い付く
- 盤に置いたままタップで向きが変わり、盤面は 5 マスのまま。Undo で戻る

`node tools/gen-solutions.mjs --check` も両方の盤で一致（8×8 65 件、
6×10 2339 件）。`logic.js` に足したのは新しい関数だけで、向きの生成
（`orientations()`・`turnOrder()`）には触っていない。

## 決めなかったこと

**閾値 2 つは暫定。** `INPUT.swipeSpeed`（0.5 px/ms）と `INPUT.snapRange`
（1 升）は、実機で触らないと決められない。振りが効きすぎる・吸い付きが
強すぎるといったことがあれば `config.js` の `INPUT` で調整する。
