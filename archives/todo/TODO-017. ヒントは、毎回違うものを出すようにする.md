## TODO-017. ヒントは、毎回違うものを出すようにする

- [x] 「毎回違う」の範囲を決める（同じ盤面で押し直したときも含めるか）
- [x] `solver.js` の探索順に乱数を入れる（ピースの順・向きの順）
- [x] 混ぜた状態で試行回数を実測し、上限（`SOLVER_LIMIT`）の中で終わるか確かめる
- [x] `tests.html` に、同じ盤面から何度も呼ぶと違う手が返るテストを足す

### きっかけ

`solve()` はピースの試す順（`unused` の並び）も向きの順（`orientations()` の
戻り順）も固定だったので、同じ盤面からは必ず同じ解が返っていた。
[一手戻す] → [ヒント] を繰り返しても毎回同じ手しか出ない。

### 決めたこと

**直前に出した手は必ず避ける。** 乱数で混ぜるだけでは、候補が少ないときに
偶然また同じ手が出る。ヒントは押すと即座に置くので、押し直す状況は実質
[一手戻す] の直後であり、そこで同じ手が出ると「毎回違う」にならない。

避けきれないときは同じ手を出す。終盤は残りのピースが少なく、そもそも違う手が
無いことがある。引き直しはそのぶん待たせるので、`HINT_RETRIES`（4 回）で
打ち切る。何も出さないより、同じでも出したほうが役に立つ。

**空きマスの若い順（`firstEmpty()`）は混ぜない。** 同じ配置を順番違いで何度も
試さないための枝刈りの前提になっている。

### やったこと

- `src/solver.js` — `solve()` に `shuffle` と `random` のオプションを足した。
  `shuffle` を真にすると、ピースの順（`unused`）と向きの順（`shapes`）を
  Fisher-Yates で混ぜる。`random` はテストから決まった順を作るための差し替え。
  混ぜるのは呼ぶ側が指定したときだけで、既定の挙動は変えていない
- `src/config.js` — `HINT_RETRIES`（引き直しの回数）を足した
- `src/scenes/game.js` — `lastHint`（直前に出した手）を持ち、`findHint()` で
  同じ手が返るあいだ引き直す。`isLastHint()` はピース・向き・位置がそろって
  一致したときだけ「同じ手」と見なす。**一手戻しても `lastHint` は消さない**
  （消すと避けられなくなる）

### 実測

混ぜると枝刈りの効き方が変わるので、上限（`SOLVER_LIMIT` = 800 万）の中で
終わるかを Node で測った（`config.js` と `solver.js` は Phaser にも DOM にも
依存しないので、`window` だけダミーを置けば Node から直接呼べる）。

| 盤面 | 固定 | 混ぜる（最大） |
|---|---|---|
| 8×8 空の盤 | 11,315 回 | 37,820 回（20 回試行） |
| 6×10 空の盤 | 110,111 回 | 238,927 回（20 回試行） |
| 6×10 途中まで 6 個 | — | 344 回 |

ランダムに 1〜4 個置いた盤面 300 通り（詰みを含む）でも、最悪は
8×8 が 213,216 回（132ms）、6×10 が 1,057,547 回（604ms）で、
**上限での打ち切りは 1 件も出なかった**。上限の 2 割弱で収まっている。

### テスト

`tests.html` に盤ごと 5 件ずつ（計 10 件）足した。全 81 件が通る。

- `shuffle` を付けても盤面をちょうど埋める解が返る
- `shuffle` は渡した盤面もピース名の配列も書き換えない
- 同じ乱数を渡せば同じ解が返る
- `shuffle` を付けたヒントは何度か呼ぶと違う手も返る（10 回で 2 種類以上）
- `shuffle` でも上限まで使い切らない

実際の画面でも、Chromium を CDP で動かして [ヒント] → [一手戻す] を 8 回
繰り返した。8 回で 6 種類の手が出て、**直前と同じ手が続いたのは 0 回**。
