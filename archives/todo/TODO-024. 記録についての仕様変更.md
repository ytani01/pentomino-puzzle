# TODO-024. 記録についての仕様変更

## きっかけ

TODO-020 で「ヒント・詰み表示を使ったクリアは記録に残さない」ことにしたが、
残さない範囲が広すぎた。`clear.js` は `shouldRecord()` が偽なら
`saveBest()` も `addHistory()` も `addFound()` も呼ばないので、**解けた回
そのものが消えていた**。

- あとから「どのパターンを解いたか」を辿れない
- 達成度（「65 解中 12 解」）にも入らないので、遊んだ実感と数が合わない
- 一方で、頼って出した時間を自己最短に混ぜたくないのは変わらない

そこで **残す範囲と、最短時間の可否を分ける**ことにした。

## やったこと

### 履歴に印を持たせる

履歴 1 件（`{ at, ms, no }`）に `h`（ヒントを使った）と `c`（詰み表示を
使った）を足した。**使ったときだけ持たせる**（偽なら鍵ごと省く）。自力で
解いた回が記録の大半になるので、そちらを今までと同じ形のままにしておけば、
TODO-024 より前に保存した件と見分ける必要がなくなる（印が無い＝自力）。

- `sanitizeHistory()` … 通った件を**組み立て直して返す**ようにした。持つ鍵を
  `at` / `ms` / `no`（または `cells`）と、真の `h` / `c` だけに絞るためで、
  知らない鍵や `h: 1` のような値がそのまま保存へ戻らない
- `migrateHistory()` … `cells` だけを番号へ差し替え、`h` / `c` は持ち越す
- `addHistory()` … **印を外すときだけ、既にある件を書き換える**。頼って
  解いた回に印が付いたあと、同じ解を自力で解き直したら印を落とす。日時と
  時間は初めに解いた回のまま残す（TODO-021 の「既にある件を書き換えない」
  を保つ）。逆に、自力で解いた件へあとから印が付くことは無い

### 最短時間だけを自力に限る

`shouldRecord()` を `shouldRecordBest()` へ改名した。見るのは最短時間だけで、
履歴と達成度（`foundKey`）には**常に**残す。

クリア画面の文言も直した。「今回は記録しない」だと一覧にも残らないように
読めるので、「今回は最短に入れない」「（記録には残る）」と、最短時間の話だと
分かる文にしてある。

### 「全部で解が何通りあるか」は対応済み

項目にあった「記録の表示では、全部で解が何通りあるかも表示する」は、
TODO-022 で既に出るようになっていた。

- 記録の画面 … 「8×8 … 65 解中 12 解」（`records.js` の達成度の行）
- クリアの画面 … 「正解の 3 番（8×8 の全 65 解）」

利用者に確かめて「これで足りている」との判断だったので、**新しく足したものは
無い**。

## テスト

`tests.html` に足した（全 192 件が通る）。

- `sanitizeHistory` … 印がそのまま通る／偽・数値・文字列の印は落とす／
  知らない鍵は落とす／印を持たない件は自力扱いのまま通る
- `migrateHistory` … 読み替えても印が残る
- `addHistory` … 頼った回も履歴に残り印が付く／印の付いた解を自力で解き直すと
  印だけ外れる（日時と時間は変わらない）／頼った回を重ねても印は増減しない／
  自力で解いた件へあとから印は付かない
- `shouldRecordBest` … 名前を変えた 4 件

実際に遊んで（headless の Chromium から `useHint()` を繰り返してクリアまで）、
履歴に `{"no":3,"h":true}` が入り、`found` にも `3` が入ることを確かめた。
