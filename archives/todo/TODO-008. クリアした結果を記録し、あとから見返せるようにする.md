## やったこと

### 履歴の保存形式

盤ごとに 1 つのキーへ、JSON の配列を新しい順で置く。

```
pentomino-puzzle/history/8x8 ・ pentomino-puzzle/history/6x10
1 件: { at: エポックミリ秒, ms: 所要時間, cells: 盤面の文字列 }
```

- `cells` は `logic.js` の `boardKey(board)` の出力そのまま（空きは `.`、
  穴は `#`、置いてあればピース名。行優先）。盤の縦横は保存先のキーで
  決まるので 1 件には持たせない
- 上限 50 件（`config.js` の `HISTORY_LIMIT`）。あふれたら古いものから捨てる
- `historyKey` は**どちらの盤も接尾辞を付けて揃えた**。`storageKey` は
  8×8 だけ接尾辞が無いが、あれは盤が 1 つだった頃の記録を引き継ぐため。
  引き継ぐものが無い新しいキーへ、その不揃いを持ち込む理由が無い

### 最短時間との関係 — 今のキーを残し、両方持つ

履歴から最短時間を導くやり方は**採らなかった**。上限で古い件が捨てられると
最短時間まで消えてしまうため。`saveBest()` と `addHistory()` は別々に呼ぶ。
`clearHistory()` も `clearBest()` とは独立にしてある。

### 壊れた値の扱い

`sanitizeHistory(value, board)` を**純関数として export** した。
localStorage の生文字列でも、パース済みの配列でも受ける。`at` / `ms` が
有限の正の数か、`cells` が文字列で長さが `rows * cols` と合うかを 1 件ずつ
見て、壊れた件は黙って捨てる（例外にしない）。

純関数を分けて出したのは、**localStorage を触らずに `tests.html` から
検証できるようにするため**。壊れた値を書き込んで読み直す手順が要らない。

### 記録の画面（`src/scenes/records.js`）

タイトルに「記録」ボタンを 1 個足して開く。

- **画面の中で盤を切り替えられる**。タイトルへ戻って選び直させると、
  記録を見比べるだけで画面を 2 往復することになるため。切り替えても
  `registry` は書き換えない（見ているだけで、遊ぶ盤は別）
- **一覧は頁送り。スクロールは採らなかった。** Phaser には当たり判定を
  持つ行をはみ出させずに流す仕組みが無く、カメラかマスクを別に用意する
  ことになる。50 件なら 1 頁 9〜10 件で 5 頁に収まるので、送る手数より
  作りの単純さを取った
- **完成形は `Graphics` で描く。テクスチャは貼らない。** `boot.js` の
  テクスチャは盤（64px）とトレイ（20px）の大きさで焼いてあり、この画面の
  マス（44〜56px）に合う 1 枚が無い。縮小して貼ると立体の帯や光の筋が
  つぶれ、かえって塊の境目が分かりにくくなる。塗りと、隣が別のピースに
  なる辺の線だけで描いた
- 消すときは画面内（Canvas 上）で確認を出す。`game.js` のタイトルへ戻る
  確認と同じ組み。履歴が空のときは「消す」を押せなくしてある
- `title.js` の `createChoiceRow` は `ui.js` へ移した。記録の画面も盤の
  切り替えに同じ行を使うので、「今どれが選ばれているか」の見え方を揃えるため

タイトルは「記録」の行を足したぶん横画面の 640 に収まらなくなるので、
`howTo` / `palette` / `best` / `start` のあとの間隔を詰めた（合計 604）。

## テスト

`tests.html` に 22 件足した（`sanitizeHistory` 8 件、保存して読み出す
14 件＝2 盤 × 7 種類）。**全体で 127 件すべて通る。**

本物の localStorage を触るテストは、**利用者が実際に遊んだ記録を消して
しまわないよう**、対象のキー（`historyKey` と `storageKey` の両方）を
退避して `try` / `finally` で必ず戻す（`withCleanStorage()`）。

画面は Playwright 同梱の Chromium で、横画面・縦画面（375×667）・
568×320・確認表示・12 色・記録なしを撮って、はみ出しが無いことを確かめた。
