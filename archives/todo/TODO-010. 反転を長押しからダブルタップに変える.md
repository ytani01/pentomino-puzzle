# TODO-010. 反転を長押しからダブルタップに変える

## きっかけ

今までは押下から `INPUT.longPressMs`（420ms）で反転し、`dragThreshold` を
超えて動いたらドラッグ、どちらでもなければ離したときに回転、と 1 つの押下を
3 つに振り分けていた。長押しは反転までの待ち時間が長く感じられるうえ、
「押しっぱなしにする」という操作がスマホでは分かりにくい。ダブルタップに
変えれば、待つ動作は無くなり、長押しとドラッグの取り違えも起きなくなる。

1 回目のタップで先に回転してしまうと、ダブルタップは「回転してから反転」に
見えてしまう。**1 回目の回転を `INPUT.doubleTapMs` だけ遅らせて待つ**か、
**2 回目が来たら 1 回目の回転を取り消してから反転する**かを検討し、
前者（回転を遅らせる）に決めた。単発タップの反応が少し鈍くなるより、
反転の直前に絵が跳ねるほうが目に付くと判断した。

## やったこと

| ファイル | 変更 |
|---|---|
| `src/config.js` | `INPUT.longPressMs` を `INPUT.doubleTapMs`（320ms）に置き換え |
| `src/scenes/game.js` | 長押しの判定を捨て、離したときにダブルタップを判定する形に書き換え |

- **押下時（`onPiecePointerDown`）はもう何もタイマーを仕掛けない。** 長押し用の
  `timer` と `locked` を廃止し、押下はドラッグへ移るかどうかの起点にするだけにした
- **離したとき（`onPointerUp`）に、直前の待機中のタップ（`this.pendingTap`）と
  同じピースかどうかを見る。** 同じピースで、間隔が `INPUT.doubleTapMs` 以内、
  かつ位置のずれが `INPUT.dragThreshold` 以内なら 2 回目のタップと見なし、
  待っていた回転を取り消して反転する
- そうでなければ、このタップを 1 回目として `this.pendingTap` に控え、
  `INPUT.doubleTapMs` 後に回転を実行するタイマーを仕掛ける。2 回目が来れば
  そのタイマーを取り消すので、回転と反転が両方走ることはない
- **ドラッグが始まったら、そのピースぶんの待機中のタップは捨てる。** 1 回目の
  タップの直後に同じピースをつかんでドラッグへ移った場合、ドラッグ中や
  ドラッグ後に古い回転が割り込まないようにするため（`startDrag()` の先頭）
- シーンを離れるときに待機中のタップも捨てるよう、`shutdown` に
  `cancelPendingTap` を追加登録した

## テスト

`game.js` の入力は Phaser の Pointer に依存し、`tests.html`（純関数のみ）の
対象外。見た目と挙動は、ヘッドレス Chromium を Chrome DevTools Protocol で
直接操作して確かめた。

- **トレイのピースで単発タップ** → `doubleTapMs` 待った後に回転した
- **トレイのピースでダブルタップ** → 回転を経ずに反転した
- **盤の上のピースで単発タップ** → 待った後にその場で回転した
  （`canPlace` で置けることを確認したうえで）
- **盤の上の非対称なピース（F）でダブルタップ** → 形が反転して変わった
  （`I` の水平置きでは反転しても同じ形になるため、音だけで見た目は変わらない
  ことも確認した。これは向き変更の対称形と同じ扱いで、想定どおり）
- **`mobile: true` のタッチイベントで**、単発タップ（トレイの `F`）は
  ドラッグへ移らず遅延回転し、別のピース（トレイの `I`）を大きく動かす
  タッチは回転・反転を経ずに盤へドラッグ配置された。取り違えは起きなかった
- 一連の操作の後、`scene.pending` / `scene.drag` / `scene.pendingTap` が
  すべて `false` に戻ることを確認し、状態が残らないことも見た
