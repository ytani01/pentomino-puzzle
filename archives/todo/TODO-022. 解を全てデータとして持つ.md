# TODO-022. 解を全てデータとして持つ

## きっかけ

ヒントも「解の有無を教えるモード」も、そのつど探索して求めていた
（`src/solver.js`）。6×10 の詰みの盤面でヒントを押すと **2.8 秒画面が止まり**、
上限で打ち切ったときは「解が無い」と言い切れないので「？？？」と出していた。

解は数が知れているので、**あらかじめ全部数え上げて持てば**、探索そのものが
要らなくなる。ついでに、保存する履歴は解の番号だけで足りるようになり、
「全何解のうち何解を見つけたか」も出せる。

### 調べた結果（2026-08-15 実測）

| 盤 | 全解 | 代表形（回転・反転をまとめた数） |
|---|---|---|
| 8×8（中央 2×2 穴） | 520 | 65 |
| 6×10 | 9356 | 2339 |

代表形の数は、文献にある 65 / 2339 と一致した。

**実行時に列挙するのは無理。** 6×10 は Node でも数分かかる（実測 327 秒。
調査時の 144 秒との差は機械の混み具合で、どちらにせよ実行時には使えない）。
事前に生成してコミットするしかない。**逆に、作るのは 1 回だけなので生成を
速くする工夫は要らない**（Dancing Links を持ち込む、探索順を練る、といった
ことをしない）。`solver.js` の枝刈りをそのまま流用した素朴な作りで足りる。

なお、この数分は上限でもある。ペントミノが敷き詰められる長方形は
6×10（2339）・5×12（1010）・4×15（368）・3×20（2）で、**解が一番多い
6×10 を既に測っている**。盤を足しても生成時間がこれより大きく延びることはない。

**圧縮の工夫は要らない。** 代表形を 1 行の文字列で持つと 8×8 が 4.1KB、
6×10 が 139.3KB。1 マス 4bit に詰めれば 68.5KB まで半分になるが、
**gzip をかけると 38.9KB 対 38.0KB でほとんど差が消える**。GitHub Pages が
実際に gzip で返すことは公開中の `src/config.js` で確かめた（25KB が 9.8KB で
届く。Brotli は要求しても返らなかった）。読みにくい形式にしてまで縮める理由が
無いので、`boardKey()` の出力をそのまま並べて持つ。

## やったこと

### 全解のデータを作る

- `tools/enumerate.mjs` … 全解の数え上げ。`src/solver.js` を**移して**、
  「1 解見つけたら止める」のをやめただけ。枝刈り（空きマスの若い順、空き領域が
  5 の倍数か）はそのまま。試行回数の上限は持たない（最後まで数え上げるのが
  仕事なので、打ち切る意味が無い）
- `tools/gen-solutions.mjs` … `src/data/*.js` を書き出す。`--check` を付けると
  作り直して今あるものと突き合わせ、違えば終了コードを立てる
- `tools/window-shim.mjs` … Node から `src/` を読むためのダミーの `window`。
  `src/config.js` がトップレベルで `window.innerHeight` を触る（`PORTRAIT`）ため

Node は `.js` でも構文検出で ES Modules として読めるので（v22.7 以降）、
`package.json` を足さずに `src/logic.js` などをそのまま流用できた。
GitHub Actions 側は既定の Node が古いことがあるので `actions/setup-node`（24）
を足してある。

### データの置き場所と形

- `src/data/8x8.js` ・ `src/data/6x10.js`。1 行が 1 つの代表形で、
  `logic.js` の `boardKey()` の出力そのまま
- **`src/` の下に置く。** `.github/workflows/pages.yml` は公開するものを
  `index.html` と `src/` だけと列挙しているので、`data/` を `src` の外に作ると
  ローカルでは動くのに公開先で 404 になる
- **並びは文字列の昇順に固定**し、その順番（1 から数える）を解の番号とする。
  代表形は `canonicalBoard()` で一意に決まるので、作り直しても番号がずれない

### 遊ぶ側

`src/solutions.js` を新しく置いた。

- **6×10 のデータは、その盤を選んだときだけ読む**（動的 import）。
  タイトル画面と 8×8 では 139KB を読まない
- 読み込んだあと `boardSymmetries()` で回転・反転を展開してから盤面と
  突き合わせる（展開後は 520 件 / 9356 件）
- 覚えておく先は `game.registry`。書き換わる状態をモジュールのトップレベルへ
  持たせない決まりに合わせた（盤や色の選択と同じ扱い）
- ヒントは**条件に合う解から無作為に 1 つ選ぶ**。どのピースを置くかは今までどおり
  「一番若い空きマスを覆う 1 手」

### 速さ（ここが一番大きい）

「1 個だけ置いた盤面」を総当たりして測った最悪の時間（Chromium）。

| | 今まで（探索） | 全解データ |
|---|---|---|
| ヒント（6×10） | **2795 ms** | **1.1 ms** |
| ヒント（8×8） | 329 ms | 0.8 ms |
| 詰み表示（6×10） | 273〜280 ms | 1.3 ms |
| 起動時 | 0 | 20 ms（6×10 の展開） |
| メモリ | 0 | 1.07 MB（展開後 9356 件） |

**打ち切りの曖昧さも消えた。** 6×10 の 1 手目で詰む置き方は 2056 通り中
**184 通り**で、今はその全部を「解なし」と言い切れる。前は上限内で
言い切れたのが 166 通りだけで、85 通りを「？？？」と出していた
（そのうち実際に詰みだったのは 18 通りだけ）。

### 消えたもの

`SOLVER_LIMIT`、`SOLVE_CHECK_LIMIT`、`SOLVE_CHECK_DELAY`、`HINT_RETRIES`、
`solve()` の `'limit'` と `shuffle`、`checkState` の `unknown`（「？？？」）、
`config.js` にあった上限の根拠を書いた長いコメント、`game.js` の
`findHint` / `isLastHint` / `scheduleCheck` / `cancelCheck`。

`SOLVE_CHECK_DELAY` を消したのは、待たせていた理由（置いたピースが収まる動きの
最中に画面を止めない、続けて操作したぶんを間引く）が 1ms 台では意味を持たなく
なったため。今は盤が変わったその場で調べる。

### 記録

- **履歴 1 件は `{ at, ms, no }` になった。** 60 マスぶんの文字列は持たない。
  重複の判定（TODO-021）も番号の一致を見るだけで済む
- **TODO-022 より前に保存した件（`cells` を持つ）は番号へ読み替える**
  （`migrateHistory()`）。捨てずに済み、書き戻したときに番号へ揃う
- **見つけた解の番号は履歴とは別に貯める**（`BOARDS[key].foundKey`）。
  履歴は 50 件で頭打ちになるので、6×10 の全 2339 解に対する達成度を
  そこから数えると 2.1% で止まってしまう。番号だけなら 2339 件でも 12KB ほど

### 画面

- クリアの画面に「正解の 42 番（8×8 の全 65 解）」の行を足した。枠を 20 だけ
  高くしてある。回転・反転して置いても同じ番号になる
- 記録の画面に達成度「8×8 … 65 解中 4 解」を足した。**盤の名前を頭に付ける**のは、
  分母が盤で違う（65 と 2339）ため。付けずに「65 解中」とだけ出すと、
  6×10 の話と読み違える
- 記録の一覧で選んだ 1 件の見出しに「65 番」を足した。一覧の行そのものは
  日時と時間だけのまま（幅を揃えたいので）

### データとコードのずれを防ぐ

**公開のときに検査する。** `.github/workflows/pages.yml` で
`node tools/gen-solutions.mjs --check` を走らせ、コミットしてあるデータと
突き合わせて、違っていればジョブを失敗させる（`VERSION` のプレースホルダを
検査しているのと同じやり方）。6×10 の生成に数分かかるが、タグを押したときだけ。

## 拡張性で失うもの（**受け入れると決めた**）

1. **盤を足すたびにデータの生成が要る**（前は `BOARDS` に足せば `solver.js` が
   そのまま動いた）
2. **動的な盤が作れない**（穴の位置を毎回変える、遊ぶ人が盤を描く、など）
3. **ピースを増やす方向が閉じる**（ヘキソミノなどは解の数が桁違いで持てない）
4. データとコードがずれると、間違ったヒントを静かに出す
   → 4 だけは上の検査で防いでいる
