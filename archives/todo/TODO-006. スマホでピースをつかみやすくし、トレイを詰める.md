# TODO-006. スマホでピースをつかみやすくし、トレイを詰める

## きっかけ

スマホで遊ぶとトレイのピースをつかみにくかった。内部解像度 960x640 を
`Scale.FIT` で縮めるので、568x320 では倍率が 0.5 になり、`tray.cell = 22`
（`config.js`）は画面上で 11 CSS px にしかならず、指のタップ目標の目安
44px を大きく下回っていた。当たり判定はピースの形そのままで、`L` や `U`
の凹んだところは反応しなかった。

## 決めたこと

- `tray.cell` を 22 から 20 へ下げる。トレイの中でも `I` を横向きに
  回転できるので、`5 × tray.cell` の幅が下限になる。20 なら 100px。
- 空いた幅は盤に回す。盤は高さが頭打ちなので、マスは 64 内部px が上限
  （`board.y = 84`、メッセージが `y = 612` に収まる範囲）。
- 3 列 4 行のレイアウトはそのまま（12 種がちょうど収まる）。
- ずれたときの「盤の上か」の判定は、指の位置ではなく見えているピース
  （`container`）の位置に揃える。
- ずらすのはタッチ操作のときだけ（`pointer.wasTouch`）。マウスでは
  指がないのでずらさない。
- ずらし幅は盤のマス 1 個ぶん。

## やったこと

`src/config.js` の `LAYOUT` を書き換えた。

| | 前 | 後 |
|---|---|---|
| `board` | `x: 24, y: 84, cell: 56` | `cell: 64` |
| `boardPanel` | `468x468` | `532x532` |
| `tray` | `x: 500, width: 426, cell: 22` | `x: 560, width: 366, cell: 20` |
| `trayPanel` | `x: 490, width: 446` | `x: 550, width: 386` |

`src/scenes/game.js`:

- `createTraySlots()` を新設した。トレイの各スロットに透明な矩形を
  1 枚重ね、`pointerdown` を受けて対応するピース（`piece.slot` で固定）
  へ渡すようにした。ピースの絵そのもの（タイル単位の当たり判定）は
  盤に置いたピースのぶんだけ残る。
- `startDrag()` で、`pointer.wasTouch` のときだけ `offsetY` に
  `LAYOUT.board.cell`（内部px）を足し、ピースを指より上へずらすように
  した。
- `dropSpot()` の「盤の上か」の判定を、指の位置（`pointer`）から
  ドラッグ中の Container の位置に変えた。ピースをずらしたぶん、指の
  位置で見ると盤の下端でずれが起きるため。これに伴い `dropSpot()` /
  `dropDrag()` は引数の `pointer` を使わなくなったので取り除いた。

## テスト

- `tests.html`：39 件すべて通った（今回の変更は計算ロジックに触れて
  いないので、影響なし）。
- Playwright 同梱の Chromium をヘッドレスで立て、568x320 と 667x375 で
  タイトル→ゲーム画面を撮って、盤とトレイがどちらもはみ出さずに収まる
  ことを確認した。
- ヘッドレス CDP からの `Input.dispatchTouchEvent` は、ブラウザの
  DOM イベント（`touchstart` / `pointerdown`）までは届くのに、Phaser の
  入力プラグインには渡らなかった（原因は未特定。ヘッドレス特有の
  制約と見られる）。そのため実際のタッチドラッグは再現できず、
  マウスの `pointerdown` でトレイのスロット当たり判定が働くことを
  確認したうえで、`startDrag()` を `wasTouch: true` の疑似ポインタで
  直接呼び出し、`offsetY` が盤のマス 1 個ぶん増えて Container が
  上にずれることをコンソール越しに確かめた。実機のタッチ操作での
  最終確認はしていない。
