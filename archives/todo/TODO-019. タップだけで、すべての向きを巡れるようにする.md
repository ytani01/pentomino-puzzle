# TODO-019. タップだけで、すべての向きを巡れるようにする

## きっかけ

ピースの回転と反転が別々の操作になっていた。タップは `rotateCw` だけを
呼ぶので、1 つの向きから辿れるのは 4 通りまで。鏡像へ行くにはダブルタップ
（`flip`）を挟むしかなく、目当ての向きにするのに 2 種類の操作を
使い分ける必要があった。

タップだけで「回転 → … → 裏返し → 回転 → …」と全部の向きを巡れるように
した。ダブルタップの裏返しは、狙った向きへ一足飛びに行く手段として残す。

## やったこと

### 巡る順（`src/logic.js`）

`orientations()` は「表を 4 回転 → 裏を 4 回転」の順に作るが、裏の起点が
`flip(元の向き)` なので、5 番目で絵が別の角度の鏡像へ飛んで見える。
そのままタップの順には使えなかった。

`turnOrder()` を別に足した。裏の起点を「表の最後の向きをその場で
裏返したもの」に取るので、隣り合う向きの変化は必ず 90° 回転か、その場の
裏返しのどちらかになる（並びの最後から先頭へ戻るところも裏返しになる）。
F ならこう巡る:

```
##    |   #   |  #    |  #    |  #    |  #    | #     |  ##
 ##   | ###   | ##    | ###   | ###   |  ##   | ###   | ##
 #    |  #    |  ##   | #     |   #   | ##    |  #    |  #
      回転 →      回転 →   裏返し     回転 →     回転 →   （先頭へ裏返し）
```

`orientations()` 自体の並びには手を入れていない。探索の順を変えると
`solver.js` の試行回数（TODO-017 で実測したもの）が変わってしまうため。

**起点を固定するのが要る。** 最初は「今の向き」から並びを作っていたが、
それだと `nextTurn()` の返す先が今の向きに依存し、表側の 4 通りだけを
ぐるぐる回って裏へ行けなくなった（テストの「F に通らない向き」で気づいた）。
`baseTurn()` で、全向きのうち `shapeKey()` が最小のものを起点に固定した。

`nextTurn(cells)` が、その並びの次の向きを返す。最後まで来たら先頭へ戻る。

### タップの処理（`src/scenes/game.js`）

`onPointerUp` の遅延実行が呼ぶ先を `rotateCw` から `turnPiece()` に変えた。
`turnPiece()` は `nextTurn()` の結果が「その場の裏返し」に当たるかを見て、
回転の音と裏返しの音を選び分ける。

`INPUT.doubleTapMs` ぶん遅らせてダブルタップを待つ作りはそのまま。連打しても
向きの変化が溜まることはない（2 回目のタップはダブルタップ＝裏返しに
差し替わるため）。盤に置いてあるピースの制約（向きを変えると置けない場合は
断る）は `applyOrientation()` にまとまっているので、手を入れていない。

### 決めたこと

- **X の扱いは今までどおり。** 向きが 1 通りしかないので、タップしても形は
  変わらず、回転の音だけが鳴る。無反応にするより、タップが届いたことが
  伝わるほうがよいと判断した（`applyOrientation()` に元からあった扱い）
- **I は 2 通りを行き来する。** 縦と横が交互に入れ替わるだけで、他の
  ピースと同じ操作感になる
- **タイトルの説明**（`src/scenes/title.js`）を
  「タップ … 次の向きへ（回転と裏返しを順に巡る）」に変えた。
  568×320 でも説明の枠からはみ出さないことを確認した

## テスト

`tests.html` に 4 件足した（全 85 件が通る）。

- `turnOrder` は `orientations` と同じ向きを、重複なく並べる
- `turnOrder` の隣どうしは、90° 回転かその場の裏返しで移れる
  （並びの最後から先頭へ戻るところも含む）
- `nextTurn` を向きの数だけ繰り返すと元へ戻り、途中で全部を通る
- X は `nextTurn` でも向きが変わらない

実際のゲーム画面でも、CDP から `turnPiece()` を 8 回呼んで確かめた。
F は 8 通りすべてを通って元へ戻り、I は 2 通り、X は 1 通りのまま。
