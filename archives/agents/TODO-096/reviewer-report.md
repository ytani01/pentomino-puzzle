## 検討

### 2. テンプレートリテラルの動的 import は付け漏れの検出をすり抜ける（`tools/stamp-version.mjs:24-26, 51`）

- 何が起きるか: `` import(`./data/${key}.js`) `` の形は置換されず、付け漏れの検出
  （`['"]…\.js['"]`）も引用符が `'` `"` だけなので拾わない。版の無い URL で読まれ、
  ジョブは成功する（「静かに古い版が混ざる」状態）
- 実測: `import { x } from './y.js';` とテンプレートリテラルの動的 import を 1 行ずつ
  置いたファイルで exit=0、`1 か所に ?v=v1 を付けた`。動的 import は無版のまま残った
- 今のコードでは起きない（`src/solutions.js:31-32` は単一引用符の固定文字列）。
  盤を足すときに `key` から組み立てたくなる箇所なので、検出の文字クラスに
  バッククォートを入れるか、文書の「import は `from './x.js'` の形で」に
  動的 import も固定文字列で書く旨を添えるかは判断が要る。実害は未確認

### 3. コメントに引用符付きのパスを書くとジョブが失敗する（`tools/stamp-version.mjs:50-52`）

- 何が起きるか: 付け漏れの検出は行単位の正規表現で、コメントかどうかを見ない。
  `// 例: 'src/data/8x8.js' を読む` のようなコメントがあると失敗する
- 実測: 上のコメントを置いたファイルで exit=1、該当行が `::error::` の下に出た
- 今の `src/` と `index.html` にはこの形は無い（`rg "['\"](\.{1,2}/|src/|/)[^'\"]*\.js" src index.html`
  で import 以外の該当は `index.html:88` の `<script src="src/main.js">` だけ。
  コメント中のパスはすべてバッククォート）。失敗する側に倒れるので公開は止まるだけで、
  壊れた版が出ることはない。逆に、コメント中の `` `from './x.js'` `` は置換の対象になり
  書き換わるが、動作には影響しない。どちらも実害は未確認
- 文書（`docs/developer.md:623-624`）は「二重引用符の import など」とだけ書いており、
  コメントでも落ちることは書いていない

### 4. リロードで新しい版が出るのは `index.html` が再検証される前提（設計）

- `index.html` 自体の URL は変わらず、これも `max-age=600` でキャッシュされる。
  新しい `?v=` が効くのは、リロードで主文書（`index.html`）が再検証されるから。
  主要ブラウザはリロード時に主文書を再検証するが、スマホのブラウザ（特に iOS Safari、
  ホーム画面に置いた場合）でも同じかは未確認
- 普通に開き直した（リロードではない）場合は、10 分以内なら古い `index.html` → 古い
  `?v=` のまま古い版が出る。項目の題は「リロードで」なので範囲内だが、
  文書（`docs/developer.md:620-622`）の書き方だと「公開直後から必ず新しい版」と
  読めなくもない。書き足すかは判断が要る

## 好みの範囲

### 5. タグ名に `'` を含むと JS が壊れる（`tools/stamp-version.mjs:20`）

- `encodeURIComponent` は `'` `(` `)` `!` `*` を符号化しない。git のタグ名には `'` を
  使えるので、`v1'x` を渡すと `from './y.js?v=v1'x';` になり構文エラー
  （実測: exit=0 のまま出力、`node --check` で SyntaxError）
- ただし同じタグ名では、前の段の `VERSION` の置換（`sed` で `'${GITHUB_REF_NAME}'`）も
  先に壊れる。タグは `vX.Y.Z` の決まりなので実害は無いとみてよい

### 6. ルート相対の `'/src/x.js'` は置換も検出もされない（`tools/stamp-version.mjs:51`）

- 検出の正規表現は `./` `../` `src/` で始まるものだけ。`import '/src/z.js';` は
  exit=0 で無版のまま残った（実測）。今のコードに該当は無く、Pages はサブパス
  （`/pentomino-puzzle/`）で公開されるのでこの書き方自体がそもそも動かない

## 問題なしとしたもの（1 行ずつ）

- `from` を含む識別子（`streak.from`、`const from = …`）: 直後が `'` でないので当たらない
- 複数行の import（`import {\n …\n} from './config.js';`）: `from` とパスが同じ行にあり置換される。`from` の後で改行しても `\s*` で拾う
- `?v=` の二重付け: 置換の正規表現は `.js'` で終わることを要求するので、付けたものには再び当たらない。2 回走らせると `count === 0` で失敗する（CI では 1 回だけなので問題なし）
- 置換は関数で返しているので、版の中の `$` が置換パターンとして解釈されることはない
- 版の空文字: `!version` で弾く
- 段の順番: `VERSION` の置換 → `dist/` へ集める → 版を付ける → `configure-pages` → upload → deploy。`run` の既定シェルは `bash -e` なので、node が非 0 で終われば以降の段は走らず公開されない
- `${GITHUB_REF_NAME}` は二重引用符で渡しており、シェルでの分割は起きない
- `CLAUDE.md` の規約: 依存を足していない（Node の標準の `node:fs` `node:path` だけ）、アセットを足していない、`src/` の手元のコードは書き換えない
- `CLAUDE.md` の表の 1 行と `docs/developer.md` の公開の節は、実装（対象・失敗条件・手元での試し方）と合っている
