## 2. デスクトップ 1280×720・マウス

トレイの F をつかみ盤の上（960×640 系で `boardX+3.5cell, boardY+3.5cell`）まで運んだ状態で、右クリック 1 回→ホイール下 1 回→ホイール上 1 回。

- `piece.cells` の推移（正規化前の実値）:
  - つかんだ直後: `[[0,1],[0,2],[1,0],[1,1],[2,1]]`
  - 右クリック後: `[[0,1],[1,0],[1,1],[1,2],[2,2]]`
  - ホイール下後: `[[0,1],[1,1],[1,2],[2,0],[2,1]]`
  - ホイール上後: `[[0,1],[1,0],[1,1],[1,2],[2,2]]`（右クリック後と**完全一致**。ホイール上は直前の「次」を打ち消す）
- マウスの下にあるマス（`container` の位置とつかんだ点 `drag.offsetX/Y` から逆算した、ピース座標系でのマウス位置 `relRow/relCol`）:
  - つかんだ直後: `(1.472, 1.472)` → 整数マス `(1,1)`
  - 右クリック後: `(1.472, 1.528)` → `(1,1)`
  - ホイール下後: `(1.528, 1.528)` → `(1,1)`
  - ホイール上後: `(1.472, 1.528)` → `(1,1)`
  - **4 回とも整数マス `(1,1)` のまま**。かつ `(1,1)` はどの `piece.cells` にも含まれる。連続座標の小数部が毎回わずかに動くのは、回転で連続点が写る位置が向きごとに変わるため（`turnPivot()` の性質どおりで、実害ではない）。

- Undo（`undo()`）1 回で、盤面が置く前と完全に戻った（`board changed after undo: true`。置く前後の `board.grid` の diff で F のマスが消えたことも確認）。

## 3. モバイル 844×390・CDP タッチ（`hasTouch`）

1 本目（id=1）でつかんで動かし、2 本目（id=2）で 3 回タップ→離す（3 回目は HUD の「一手戻す」ボタンの真上）。

- 1 本目でドラッグ開始: `drag.pointer.id === 1`、`touchShiftX/Y = [55, 0]`（横画面での 1 マスぶんのずらし）。
- 2 本目のタップ 3 回とも `piece.cells` が変化（向きが変わった）:
  - tap0: `[[0,1],[0,2],[1,0],[1,1],[2,1]]` → `[[0,1],[1,0],[1,1],[1,2],[2,2]]`
  - tap1: → `[[0,1],[1,1],[1,2],[2,0],[2,1]]`
  - tap2（Undo ボタン上）: → `[[0,0],[1,0],[1,1],[1,2],[2,1]]`
- 3 回とも `drag.offsetX/offsetY = (137.5, 82.5)`、`touchShiftX/Y = (55, 0)` は**一切変化なし**（ピースと 1 本目の指の位置関係が保たれている）。`drag.pointer.id` も 3 回とも `1` のまま（ドラッグは続いている）。
- 3 回目（Undo ボタン上）でも `history.length` は `0` のまま（一手戻っていない）。
- 最後に 1 本目を離すと `drag` が `null` になり（盤へ置かれた）、コンソールエラー 0 件。
- **CDP のクセ**: 2 本目「だけ」を離すには `touchEnd` にその指自身の点（id=2）だけを載せる必要があった。`touchEnd` に 1 本目の点（id=1）を載せると 1 本目が離れてしまう（実測。ドラッグが終了し `history.length` が `1` になった）。implementer・reviewer の報告にある実測と同じ挙動。
