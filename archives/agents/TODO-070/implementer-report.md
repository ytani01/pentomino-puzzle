## 各案の意図

- **A**（`depthFirstA` / `randomA`）: 3×3 の格子の 9 点をスネーク状（左上→右→下→左…）に
  線でつなぎ矢印で終える（＝決まった順） ／ 同じ 9 点を格子から外した位置に大きさもばらばらに
  散らす（＝ばらばら、線でつながない）。
- **B**（`depthFirstB` / `randomB`）: 1 段ずつ上がる 3 段の階段＋先へ続く矢印（＝一段ずつ着実に進む）
  ／ 左右に大きく振れるジグザグの線＋矢印（＝迷いながら進む）。
- **C**（`depthFirstC` / `randomC`）: 歯車（歯を 8 枚、中心に軸穴）＝機械 ／
  吹き出し（尻尾の丸 2 つ）の中に「？」（弧＋縦棒＋点）＝人が考える。

いずれも `U = ICON.size / 2` の単位・`begin()` を使い、既存の速さの三角
（右向き三角）・虫眼鏡（`next`）・ミュート（スピーカー＋×）・ホーム（家の形）とは
輪郭が異なる形にしてある。

## 差し替え方（撮る担当向け）

HUD の探し方ボタンは `demo.js` で `ICONS.depthFirst` / `ICONS.random` を渡している。
差し替えずに `browser_evaluate` で見た目だけ確かめるなら、ボタンを作り直さず
アイコン関数を直接呼び出して比較キャンバスに描くのが早い。ボタンに実際に
差し込んで見るなら、対象のボタンを持つコンテナの `setIcon`（`ui.js` の
`createButton` が返すもの）に案の関数を渡す。例:

```js
() => {
  const scene = window.game.scene.getScene('Demo');
  scene.strategyButton?.setIcon?.(window.ICONS_MODULE_TEST); // 実際は import 経由
}
```

`ICONS` はモジュール内の named export なので、ページ側から直接触るには
`import('./src/icons.js')` を評価内で行い、返ってきた `ICONS.depthFirstA` などを
使う。もしくは一時的に `src/icons.js` の `depthFirst`/`random` の中身を
選んだ案の中身にコピーして差し替え、通常の画面遷移（タイトル→デモ→速さ/探し方の
ボタン）で確認するほうが、実際の見た目（色・押した状態の変化）に近い。

案を選んだら、選んだ組を `depthFirst`・`random` の中身に差し替え、
`depthFirstA`〜`randomC` は削除する（このプロジェクトの規約で試作を残さない）。

  プロセス単位でサンドボックスされているとみられる。Playwright MCP
  （別ホストで動く）経由なら通る可能性がある。確認担当が MCP を使う場合は
