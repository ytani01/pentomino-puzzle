## 要修正

### 1. `tests.html:1614-1674` — 足した 3 本が、題名に書いた壊れ方をどれも捕まえない

- 問題: 上の表のとおり、崩しの回数・手数・消し方のどれを壊しても、足した 3 本は
  「崩しが一度も起きなかった」以外では落ちない。捕まえているのは、直した既存テスト
  （`tests.html:1390`）のほうだけ。
- 根拠（コード）:
  - `tests.html:1629`・`1652` の `.filter((c) => c.ok)` で、手元の規則では崩すはずなのに
    remove が続かなかった回（`ok: false`）を**捨てている**。崩しが遅れる・手数が
    足りない実装の食い違いは、失敗として数えられずに消える。`ok: false` には
    「手数の上限で打ち切った」場合も入っているので、それと分けずに捨てていることになる
  - `tests.html:1586-1596` は `expectedMoves` 回までしか読まないので、`actualMoves` が
    `expectedMoves` を超えることがない。多く外す実装は捕まらない（`moves + 1` で実測）
  - 2 本目の `assertSame(c.count, TEST_COLLAPSE_AFTER)` は、手元の規則が崩したあとに
    回数を消すので、記録される崩しでは必ず成り立つ（実装ではなく手元の写しを
    確かめている）
- どうすればよいか: 打ち切りと食い違いを分け、食い違い（`ok: false` で打ち切りでないもの）
  は失敗にする。崩しの最後の remove の次が、置ける手が残っているのに remove なら失敗にする
  （直した既存テストの「次は place」と同じ確かめ方）。あるいは、足した 3 本と
  `collectCollapses()` を削り、直した既存テストに一本化する（下の「作り込みすぎ」）。
  どちらにするかは管理者の判断。
