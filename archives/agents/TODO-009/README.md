# TODO-009 の分担

[TODO-009. 盤のサイズに 6×10 を選べるようにする](../../todo/TODO-009.%20盤のサイズに%206×10%20を選べるようにする.md)
で組んだ担当と、その分け方の理由。

**`.claude/agents/*.md` の定義ファイルは無い。** この項目では、担当ごとに
その場で指示を書いて起動した（役割が 1 回きりで、使い回す形にしても
次に同じ指示になるとは限らないため）。下の表がその代わりの記録。

| 担当 | モデル / effort | 受け持ち |
|---|---|---|
| 実装（親） | Opus / high | `config.js`・`logic.js`・`boot.js`・`ui.js` と 4 つのシーン。盤の持ち回り方とレイアウトの作り分けを決める所が本体 |
| measure | Sonnet / medium | 6×10 での求解の試行回数を実測（空の盤面と、1 個だけ置いた 2056 通りの総当たり） |
| tests | Sonnet / medium | `tests.html` を両方の盤で回る形に直して実行 |

## なぜこう分けたか

- **設計は分けない。** 「選んだ盤をどう渡すか」「レイアウトをいつ作るか」は
  8 ファイルにまたがる 1 つの判断で、切り分けると食い違う。ここは親が持つ
- **measure は判断が要らず、時間だけかかる。** 手順（ブラウザを立てて
  `solve()` を 2056 回呼ぶ）が決まっているので、実装と並行して回した。
  結果が出るまで 4 分ほどかかり、その間に実装を進められた
- **tests は範囲がファイル 1 つに閉じる。** `tests.html` だけを触ると
  決めてあるので、親の編集とぶつからない
- **画面の確認（スクリーンショット）は親がやった。** 担当を立てる予定
  だったが、実装の確認で Chromium と CDP のスクリプトを立てたままだったので、
  そのまま 5 枚撮るほうが安く済んだ。新しく起動すると、同じ道具立てを
  もう一度用意させることになる
