### 2. ヒント表示の回が同じ解の自力の回より速いと、「自己最短を更新」と「記録済み」が同時に出て、その時間は一覧のどこにも残らない

- 場所: `src/storage.js:304-313`（`recordCompletion()`）、`src/storage.js:229-233`（`isBetterClear()`）
- 実測: 履歴 `[{ no: 5, ms: 600 }]`（自力）に、ヒント表示の回 `{ no: 5, ms: 400 }` を
  `recordCompletion()` で入れると `{ best: 400, updated: true, status: 'kept' }`。
  履歴は 600 のまま、保存値は 400
- なぜ問題か: 変更前は「最短を更新した回は必ず `new` か `improved`」だった（自力の回
  だけが最短に入り、自力の回どうしは短いほうが勝つため）。今はクリア表示に
  「記録済み」（`TEXT_COLORS.dim`）と「8×8 の自己最短を更新」（accent）が並び、
  記録の画面には 400 の回が出ない。タイトルの最短 400 の出どころが一覧から辿れない
- `isBetterClear()` を変えないと決めた結果として起きる組み合わせなので、許容するかは
  管理者の判断（原因の切り分けはしていない）

### 3. 古い履歴では、同じ解のおまかせの回に負けたヒント表示の回が消えていて、「記録なし」が直らないことがある

- 場所: `src/storage.js:229-233`（`isBetterClear()`）と `loadBest()` の組み合わせ
- 実測:
  - 同じ番号に自力 600 とヒント表示 300（TODO-072 より前の重複）→ `loadBest()` は 600
    （`dedupeHistory()` が自力を残すため）
  - 同じ番号におまかせ 200 とヒント表示 300 → `loadBest()` は **`null`（記録なし）**
    （印の有無が同じなので短いおまかせが残り、`loadBest()` はそれを除く）
- 実害の程度: TODO-088 より前のデータだけ。ヒント表示で解いた解を、あとでおまかせを
  使ってより速く出し直すと（`recordClear()` が `'improved'` で置き換える）、ヒント表示の
  回は履歴から消えている。その盤の自力・ヒント表示の回がそれだけなら、直したあとも
  タイトルは「記録なし」のまま。TODO-088 以後の回は `saveBest()` が保存値へ書くので
  起きない。利用者の実データにこの形があるかは**未確認**

### 4. 履歴から出した最短は保存値へ書かれないので、あとから最短が延びることがある

- 場所: `src/storage.js:57-66`（`saveBest()`）、`src/storage.js:37-50`（`loadBest()`）
- 実測:
  - 保存値 500、履歴に古いヒント表示の回 300（`no: 7`）→ 300。`removeRecords([7])` の
    あと 500 に戻る
  - 保存値 5000、履歴に古いヒント表示の回 300 → おまかせの回を 50 件足して押し出すと
    5000 に戻る（`HISTORY_LIMIT`）
  - 保存値なし、履歴 300 のとき `saveBest(400)` は `{ best: 300, updated: false }` で、
    何も書かない
- なぜ問題か: 変更前の最短は保存値だけで、減ることはあっても延びることはなかった。
  今は、古いヒント表示の回に由来する最短だけが、記録を消す操作（TODO-031・TODO-071）や
  履歴のあふれで延びる。なお全件を消しても保存値の最短は残る（変更前と同じ挙動）ので、
  「一覧は空なのにタイトルに最短が出る」は元からある
- 実害は古いデータの件に限られる。許容するかは管理者の判断
